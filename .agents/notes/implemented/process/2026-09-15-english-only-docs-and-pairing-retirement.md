# Agent Note: English-only documentation and the retirement of translation pairing

Status: implemented


## Problem

The repository previously maintained a bilingual documentation corpus: every in-scope document carried an English sibling, a Chinese sibling, and a consistency record, and gates kept the three in step. The documentation direction is now English-only and the Chinese documents and records are gone, but the machinery outlived its subject: a pairing gate with nothing to pair, a merge driver that composed records for files that no longer exist, a translation skill and prompt harness with no corpus, a bilingual website projection, and per-pair switcher, link, and fence-derivation rules threaded through documentation, link, wrap, subsystem, and type-equivalence gates. Carrying an English-only corpus through a three-file protocol pays a maintenance and gate cost whose consistency benefit no longer exists.

## Decision

The documentation corpus is English-only. Removed with it: `*.zh.md` siblings, `*.i18n.yaml` consistency records, the `docs/i18n/` policy contracts, the `nulu-translate-docs` skill, the `verify-translation-pairing` gate with its manifest and expected-prompt fixtures, the pairing merge driver with its installer probe, conflict resolver, and hook verification, the localized website projection, and every per-pair rule in the documentation, link, wrap, Mermaid, subsystem, and type-equivalence gates.

Two public entry documents keep a translated sibling: [`README.es.md`](../../../../README.es.md) and [`apps/desktop/README.es.md`](../../../../apps/desktop/README.es.md), each with the `[English](README.md) | [Español](README.es.md)` switcher. They are maintained by review with no consistency record, no hash gate, and no publication projection; no other document participates in a translation pair. The siblings are reader-facing exceptions, not a corpus policy, and a third translated document triggers the [reintroduction conditions](#reintroduction-conditions).

Generated artifacts are single-language: the module graph and generated catalogs render once, the website projects `docs/` directly, and the [release-status reference](../../../../docs/session-format-status.md) carries one `latestReleasedVersion`/`evidenceTag` record. Gates validate that single surface — [`doc-standard.spec.ts`](../../../../scripts/doc-standard.spec.ts) checks the record without a bilingual-equality comparison, and the type-equivalence check verifies one declaration set against one page set. The [documentation standard](../../../../docs/AGENTS.md) and [nulu-doc skill](../../../skills/nulu-doc/SKILL.md) no longer route translation work; the [doc-tier decision](2026-07-04-doc-tiers-and-budgets.md) keeps its tier and budget rules with the skill-split half retired here.

## Verification

Repo-wide searches for `.zh.md`, `.i18n.yaml`, `i18n`, pairing-record, and translation-machinery identifiers find no corpus files: only the version-1 archive-migration code and its tests, one trim-skill search exclusion, and the two intentional Spanish README siblings mention the retired suffixes; `package.json`, `run-gates.ts`, and `lefthook.yml` carry no pairing entries, and the deleted scripts have no importers. [`verify-md-links`](../../../../scripts/verify-md-links.ts), [`verify-md-wrap`](../../../../scripts/verify-md-wrap.ts), and [`verify-mermaid`](../../../../scripts/verify-mermaid.ts) cover the Spanish siblings as ordinary documents included in their patterns. Coverage gap: no gate rejects a newly added `.zh.md` or `.i18n.yaml` file — review owns the language policy — and a reintroduced second language must rebuild machine-checked consistency deliberately rather than slip in behind a passing gate.

## Preserved record of the retired design

The retired pairing design kept a documentation pair as three sibling files: English `foo.md`, Chinese `foo.zh.md`, and a sidecar `foo.i18n.yaml` recording both sides' git blob hashes as of the last confirmed-consistent state. Neither language was canonical — a document could be authored Chinese-first and translated to English afterwards — and pairs merged whole. The corpus-wide `verify-translation-pairing` gate inside `doc-sync` enforced pair completeness, both hashes, switchers, and structural signatures through exclusions-only discovery, so no document could opt out of the check; relative links selected the target sibling matching the source locale, a refinement owned by the archived [localized bilingual links decision](../../archived/process/2026-08-18-localized-bilingual-links.md); source-oriented gates consumed a `.zh.md` fence sequence as a derivative only when its unsuffixed sibling carried byte-identical fences. Translation was agent work with human review — a direct one-pass path plus a heavier delegated skill — and re-recording hashes was an explicit, reviewable yaml diff that also let `gen-translation-brief` recover either side's last-confirmed text without re-translating whole files.

The pairing design's recorded alternatives remain instructive: English-canonical source with an in-file fingerprint (rejected because it cannot express Chinese-first authoring), locale directories like `docs/en/` plus `docs/zh/` (no docs-site locale mapper existed, and moving every English file would churn every cross-reference), a separate translation repository (right for a docs product with independent release trains, but outside this repository's gates), interleaved bilingual files (doubles every diff and hides partial inconsistency), commit-hash records (cannot express consistency for same-PR edits), and file-timestamp comparison (formatting-only edits false-positive, unrelated edits false-negative). Locale-suffixed sibling files are the dominant Chinese big-tech convention (ant-design, arco-design, Apache ShardingSphere), none of which enforced pairing in CI; external consistency automation exists as MDN's `l10n.sourceCommit` fingerprint, Vue's stale-translation watcher, Kubernetes localization drift scripts, and Microsoft's source-hash re-translation action. This design combined the file layout with a hash-pair gate and an agent-run workflow in place of a bot service.

The retired merge mechanism made `*.i18n.yaml` use the repository-owned `nulu-translation-pairing` merge driver because two branches editing different parts of the same confirmed pair conflicted on both hash lines even when the Markdown owners merged cleanly. The hook installer registered the driver worktree-locally; a checked-in launcher probed Node/tsx before every execution and, when the runtime was unavailable, materialized Git's ordinary text result while still returning a conflict, so Git never accepted unverified metadata. The driver merged both owners, required clean merges and intact switchers and structural signature, and wrote the canonical hashes; `resolve-translation-pairing-conflicts` applied the same algorithm to a merge that had already stopped, writing every safe record as one batch. Its recorded alternatives: take-ours or Git's union driver (neither represents the merged owners), post-merge or commit hooks (too late in the merge lifecycle to clear a populated conflict), a wrapping merge command (raw Git, stack tooling, and rebases bypass it), and hosted GitHub automation (credentials and branch mutation for a problem every local checkout already has authority to solve). Its recorded consequence: GitHub's hosted mergeability did not run the worktree-local driver, so the remote conflict badge cleared only after a contributor merged and pushed the composed record.

## Alternatives considered

- **Keep the pairing machinery and retarget it to Spanish.** Rejected: only the two public entry READMEs carry a translated sibling, and enrolling two short files in the triplet protocol adds a sidecar, hash gate, and CI process where review of one diff already holds consistency.
- **Drop the Spanish README siblings along with the Chinese corpus.** Rejected: the two install-facing entry points are where a translation still earns its keep, and the reviewed sibling costs a fraction of the consistency machinery it replaces.
- **Treat this as partial supersession and keep the old notes active and cross-linked.** Rejected: nothing in the older notes remains current authority — the scripts, gate entries, hooks, manifest, fixtures, skill, and docs contracts they describe are all absent from the repository — so an active note would carry only stale facts.
- **Archive the old notes instead of consolidating them.** Rejected: the archive holds historical decisions whose rationale can still guide future work; both mechanisms here are fully retired, and the consolidation rule preserves their unique rationale in this note, leaving one owner instead of two frozen copies.

## Reintroduction conditions

A second documentation language becomes a corpus obligation, not a one-off translation, when many reader-facing documents must stay consistent across languages or a published site needs locale projection. Rebuilding then requires a pair model (locale-suffixed siblings or locale directories), a same-PR-checkable consistency signal such as the retired content-hash sidecar, corpus-wide discovery with explicit and reviewed exclusions, integration into `doc-sync`, and a translation workflow with recorded-hash briefing; the preserved record above carries the mechanics, their rejected alternatives, and the merge-driver lessons. A reintroduction is a new Agent Note that supersedes this one. Until then, the two Spanish README siblings are the only translated surface, and a third translated document is the trigger for this section.

## Consequences

- One language means one file per document: contributors edit one surface, and the docs gates, generators, website build, and link checker each process one surface instead of three. The pairing gate's dedicated gate process and the merge suite's share of the Windows exempt-heavy lane are no longer spent.
- Chinese-first authoring and equal-authority review are no longer expressible, and a translated README sibling can silently drift because nothing checks it; that risk is accepted for two review-owned entry documents and absent elsewhere by policy.
- Restoring a second language is a rebuild — pair model, records, fixtures, site projection, and translation workflow — and this note is the deliberate copy of that rationale; git history alone is not the recovery path.
- Archived notes completed the one-time version-1 manifest migration into the single English document seal, retiring their `.zh.md` and `.i18n.yaml` artifacts and switcher lines; recorded fixtures that captured Chinese model or user output keep those bytes. Both are history, not available behavior.
