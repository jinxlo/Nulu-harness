# Automatic Nulu updates

The [update workflow](../../.github/workflows/nulu-update.yml) prepares isolated candidates, qualifies the exact source commit, tests every native installer, and publishes a complete release catalog. Failed candidates leave the public downloads unchanged.

## Operation

The hourly schedule and manual dispatch use `NULU_AUTOMATION_SOURCE_REF`, defaulting to `main`, as the trusted tooling checkout. Preparation first incorporates the current `main`, then imports at most ten upstream first-parent changes within an 800 KB diff budget. The coding worker receives the upstream diff and Nulu behavior manifest. It cannot execute commands, edit tests or credentials, follow symlinks, change release tooling or policy, or replace the Nulu brand package. Unfinished adaptation, forbidden writes, unresolved conflicts, and failing validation stop the candidate. Preparation also verifies protected files after each dependency, build, and test step; lifecycle scripts cannot change release controls before the candidate is committed.

Before invoking the worker, preparation normalizes the three Git conflict inputs with the same product-branding rules and accepts only clean `git merge-file` results. Existing and incoming test assertions survive that mechanical merge; conflicting behavior, binary data and symlinks remain unresolved. Retired translation mirrors with an English owner are removed outside frozen history and test fixtures, together with their exact title-header language link. Body links and conflicted English owners remain subject to documentation validation. Existing captured Session generations are restored byte-for-byte and remain guarded during qualification; newly introduced generations remain subject to the Session tests. Bare protocol identifiers, historical-format readers, and generated technical references retain their canonical names. Applying branding again to the current Nulu checkout must produce no changes. A clean merge proceeds directly to mandatory qualification; the worker is used for unresolved conflicts or failing source checks.

`NULU_NEEDS_BASELINE=true` selects a baseline candidate without importing upstream. Clear it only after the existing application passes qualification. Root, application and package versions advance together. The protected brand manifest permits only this allocated version change; its package identity and every other field remain protected. The integrated upstream checkpoint stays on the candidate until every required check passes and that candidate reaches `main`. Its exact commit identifiers are synchronization state, permitted by the repository reference gate for that checkpoint file alone.

`WORLD_APP_TECHNOLOGIES_API_KEY_EXTERNAL` supplies the worker and mandatory live API smoke. The key is absent from dependency installation, builds and publishing. The smoke exercises public model discovery, actual inference, direct gateway streaming, streamed file-writing tools, and saved-session resume through the built CLI. Skipping these checks cannot qualify a release.

Every coding-worker response must call a tool. Its requests require tool selection with thinking disabled; the output budget remains available for source operations and explicit completion or blocking decisions. Truncated responses fail before any returned tool executes. Missing decisions and output exhaustion report the finish reason and token count without model content or reasoning.

Preparation regenerates the persistence reference, machine schema and known-event vocabulary from the adapted source declarations. It never records new expected test output; freshness, persistence-change acknowledgements and Session replay still qualify the result. After basic preparation, exhaustive source checks and native builds run concurrently; publication requires both to pass. Coverage uses the repository CI aggregate and its supported instrumentation timeout. The native matrix tests Windows x64, macOS ARM64, macOS x64, and Linux x64. It extracts or installs both the current public installer and the candidate, opens the packaged UI with isolated application and browser profiles, rejects JavaScript errors, checks version and branding, and verifies retained browser state across upgrade and restart. The smoke completes the first-run notice, defers credential setup, and expands the sidebar before checking the candidate’s mark and unclipped wordmark. Windows launches the previous installation before replacing it in the same directory, because NSIS removes the registered previous payload during installation. Windows installation and replacement each have a ten-minute limit, and the three-stage launch probe has a 25-minute outer limit; phase logs distinguish installer work from UI validation. Installer execution stays asynchronous and discards GUI output handles, so helper processes cannot keep captured pipes open. A timeout records the owned Windows process tree and disposable Actions desktop, then terminates only the installer tree. Each result records the candidate SHA. Publication requires all four records, all four installers, both macOS update ZIPs, and matching hosted checksums.

The installation fixture uses a short randomized temporary root. NSIS file operations retain the Windows path-length limit; a long fixture prefix makes the previous uninstaller fail before replacement. The fixture keeps the packaged dependency paths near the depth of a normal per-user installation without changing the installer or application checks.

The release channel remains an explicitly unsigned developer preview. GitHub release notifications lead to downloads. Signed unattended installation requires separately configured Windows signing and Apple Developer ID/notarization; this workflow does not present unsigned packages as signed updates.

The publisher stages a draft release, downloads and verifies its bytes, rejects concurrent changes to `main`, advances the qualified commit, and promotes the release. Published assets are immutable. The website reads `nulu-release.json` and retains its existing complete download list if the catalog is invalid or unavailable.

## Failure recovery

Reports are retained as Actions artifacts for 30 days. Native screenshots and upgrade evidence accompany each target. A blocked migration, missing dependency, failed platform, or checksum mismatch requires repair of that candidate; never remove a required check to publish it.

If publication fails after the `main` update, rerun the failed publish job against its original candidate. Draft upload is idempotent; the publisher refuses to overwrite a public release. Withdraw a bad public release by selecting a previously qualified release for downloads. Installed session data must not be downgraded automatically.

The independent server [watchdog](watchdog.mjs) checks for missed hourly runs and dispatches a replacement after two hours without a completed check. It records its observation locally and reports a stuck run after four hours. A published baseline switches scheduled updates to `main` once its release commit is verified as an ancestor of `main`, including when later maintenance commits have landed.

## Validation

The focused command is `node --test scripts/automation/automation.test.mjs`. It includes negative cases for foreign model IDs, endpoint changes, protected file writes, missing Mac ZIPs, partial or duplicate platform lists, foreign URLs, and invalid hashes. The broader repository and native checks remain required by the workflow.
